# InvoicePlane PHPUnit quality upgrade — 2026-08-11

## Scope and baseline

This audit was implemented on the checkout available to this agent:

- Branch: `prep/v180`.
- PHPUnit configuration: `phpunit.xml`, suites `Unit`, `Feature`, `Integration`, and `Scripts`.
- `vendor/bin/phpunit --list-tests` discovers 620 tests on this checkout (including provider-expanded cases); provider expansion must be taken from that command, not from a source grep.
- The source inventory currently finds 518 `#[Test]` methods. This includes the audit checker; it is lower than the 620 expanded cases because providers expand at runtime. It is not asserted to equal the 621-test Docker baseline or the 636-method integration-branch figure because `test/another-integration` is not present in this checkout.
- `tests/Support/assertion-quality-inventory.md` is the generated per-test audit. Its current report contains 354 healthy methods and 164 methods requiring review: 81 generic-redirect-only, 64 status-only, 12 database-presence-only, 6 generic-body-only, and 1 other review finding.

The differing numbers are expected until the integration branch is checked out and its Docker dependencies and fixtures are installed. The acceptance criterion of zero shallow successful feature tests is therefore intentionally still open.

## Rules applied

The shared test base now provides strict JSON decoding, required-key/value and collection inclusion/exclusion assertions, exact response headers/content disposition, redirect targets, HTML field/escaping/forbidden-content checks, complete database-row comparisons, and mutation snapshots. `AbstractTestCase::request()` performs application-error detection as a health check for every request; status and shell checks remain supplementary, not domain assertions.

The quality inventory flags tests whose observed assertions are only protocol status, generic HTML/body text, generic redirect success, or database presence. It is deliberately a report/check rather than an automatic rewrite: domain expectations require test-specific judgment.

## Harness repairs

- Docker resolution now uses an exact container-name match and fails on zero or multiple matches (`tests/Support/resolve-docker-container.sh`). This prevents `name=mariadb` from selecting multiple stacks.
- PHPUnit and PHPStan cache/temp paths default to writable locations under `/tmp` in the Makefile. They remain overrideable for CI or local tooling.
- Docker database preparation converts imported base tables to `utf8mb4_unicode_ci` after schema fixups, making recurring-invoice comparisons deterministic across the supported MariaDB versions.
- Existing custom-field schema fixups and baseline reseeding remain in place.

## Behavior coverage strengthened in this change

Recurring-invoice controller coverage now verifies that a seeded invoice and client are rendered, uses exact redirect destinations for stop/delete, and compares persisted state fields after stopping. This is representative of the required listing/mutation standard. The same pattern should be applied to products, clients, invoices, quotes, payments, users, templates, AJAX, guest/download, security, and external-integration suites.
